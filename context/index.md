# Planning Framework

Rules for a planning repo, in two tiers. Each tier has its own router; follow the one that matches your task, or both
when a task touches product and engineering content. A cited `planning:<slug>` id is defined in the `(planning:<slug>)`
heading of the file that owns it, in either tier.

| Tier                                               | When to read                                                                                        |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| [`./product/index.md`](./product/index.md)         | Product content — charter, registries, `epic.md` and `initiative.md`, product requirements, mockups |
| [`./engineering/index.md`](./engineering/index.md) | Engineering content — engineering requirements, derivation, assumptions, specs, slices              |
